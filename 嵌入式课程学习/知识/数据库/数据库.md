## 数据库概述

**学习数据库的方式**

1. 理解数据库编程 —— 框架
2. 熟悉对应数据库编程API的使用方式
3. **熟悉SQL优化** —— 建立索引（SQL引擎内部使用的是B + 树结构）

---

分类

- 按照“数据模型”分类
	1. 关系型数据库。如：MySQL、**SQLite**
		- 把数据存放在一张张由“行”和“列”组成的二维表里。表与表之间可以通过外键建立“关系”。
		- 特点：严格支持 **ACID 事务**（保证数据绝对准确，比如银行转账，少了一块钱都不行）。
	2. 非关系数据库。
		- **键值数据库** (Key-Value)：
			- **是什么**：就像字典，通过一个唯一的 Key 快速找到对应的 Value。
			- **特点**：读写极快，常用于缓存。
			- **代表**：**Redis**, Memcached。
		- **文档数据库 (Document)**：
			- **是什么**：数据存储为类似 JSON 的文档，不需要定义固定的表结构。
			- **特点**：非常灵活，适合结构经常变化的数据（比如用户信息）。
			- **代表**：MongoDB。
		- **列族/宽列数据库 (Wide-Column)**：
			- **是什么**：按列存储数据，而不是按行。
			- **特点**：适合海量数据的写入和分析。
			- **代表**：HBase, Cassandra。
		- **图数据库 (Graph)**：
			- **是什么**：利用“节点”和“边”来存储实体及其之间的复杂关系。
			- **特点**：极其适合做社交网络好友关系分析、风控反欺诈。
			- **代表**：Neo4j。
- 按照“架构和部署”分类
	- 单机数据库 (Single-Node)
		- **是什么**：数据库只运行在一台服务器上。
		- **特点**：简单好维护，但一旦这台机器坏了或者数据量超载，系统就崩溃了。
	- 分布式数据库 (Distributed Database)
		- **是什么**：物理上把数据分散存储在多台独立的计算机（节点）上，但在逻辑上，用户用起来感觉就像是在用一个数据库。
		- **为什么需要它**：当单机装不下、算不动海量数据时，通过“人多力量大”的方式，把数据和计算压力分摊到几十甚至几千台服务器上。
		- **特点**：高并发、高可用、易于水平扩展（加机器就能提升性能）。
		- **常见代表**：TiDB, OceanBase, CockroachDB。
- 按“应用场景”分类
	- 向量数据库 (Vector Database) — *当前 AI 的核心*
		- **是什么**：专门用来存储和快速检索高维向量（Vector）的数据库。
		- **为什么现在火**：在 AI（尤其是大语言模型、图像识别）中，图片、视频、文本等非结构化数据会被 AI 模型转化为一串数字（即“向量 Embedding”）。向量数据库能通过特定的算法（如 ANN，近似最近邻搜索），快速找出“意思最接近”的数据。
		- **应用**：大模型的外挂知识库（RAG）、人脸识别、推荐系统。
		- **常见代表**：Milvus, Pinecone, Chroma。
	-  时序数据库 (Time-Series Database)
		- **是什么**：专门存储带有**时间戳**的数据。
		- **应用**：物联网（IoT）设备每秒上传的传感器数据、股市行情、服务器监控指标。
		- **常见代表**：InfluxDB, Prometheus。
	- OLTP 与 OLAP（交易 vs. 分析）
		- **OLTP（联机事务处理）**：专注于**快速写入和修改**。比如你上淘宝下单、付款，要求高并发、绝对不能出错（MySQL、Oracle 都是此类）。
		- **OLAP（联机分析处理）**：专注于**海量数据查询与分析**。比如老板想看“过去三年全国各门店的销售趋势”，不需要实时改数据，但需要一次性扫描几十亿条数据做聚合（常见代表：ClickHouse, Snowflake）。

## SQLite

数据库[SQlite](https://sqlite.org/index.html)属于轻量级数据库， 只有几十KB（数据软件）， 一般应用在嵌入式和移动
设备中。 SQLite的源代码是C， 其源代码**完全开放**。 它具有以下特性：
（1） 零配置， 无须安装和管理配置；
（2） 储存在单一磁盘文件中的一个完整的数据库；（移动到其他地方时，通过SQLite提供的接口就能直接使用）
（3） 数据库文件可以在不同字节顺序的机器间自由共享；
（4） 支持数据库大小至2TB；
（5） 对数据的操作比目前流行的大多数数据库要快。

### SQLite的API

**对象构造器（建库连接）**：`sqlite3_open()`。

**SQL 语句编译器（准备工作）**：`sqlite3_prepare_v2()`（负责把你的 SQL 字符串编译成机器可读的底层代码，新项目一律用带有 `_v2` 后缀的这个函数）。  

**执行器**：`sqlite3_step()`（让编译好的 SQL 语句真正跑起来，去取数据或插入数据）。  

**释放器**：`sqlite3_finalize()`（释放 `prepare` 占用的内存） 与 `sqlite3_close()`（关闭数据库连接）



数据库打开：`sqlite3_open`

- **原型**：

	```c
	int sqlite3_open(const char *filename, sqlite3 **ppDb);		// ppDb用于返回sqlite3结构体
	```

- **作用**：连接到指定的 SQLite 数据库。如果该数据库文件不存在，SQLite 会自动创建它。

- **返回值**：成功返回 `SQLITE_OK`（即 `0`），失败会返回错误码，可以通过 `sqlite3_errmsg(*ppDb)` 获取具体的报错字符串。



SQL 编译：`sqlite3_prepare_v2`

- **原型**：

	```c
	int sqlite3_prepare_v2(
	    sqlite3 *db,            // 数据库句柄
	    const char *zSql,       // SQL 语句字符串
	    int nByte,              // SQL 字符串的最大长度（传入 -1 自动计算到 '\0'）
	    sqlite3_stmt **ppStmt,  // OUT: 编译好的“语句句柄”（字节码对象）
	    const char **pzTail     // 指向 SQL 语句中未编译部分的指针（通常传 NULL）
	);
	```

- **作用**：**核心概念！** 它并不执行 SQL，而是将你写的 SQL 文本编译成 SQLite 虚拟机可以理解的**字节码（Bytecode）**，并将这个字节码保存在 `sqlite3_stmt`（语句句柄）中。

- **为什么新项目一律用 `_v2`**：老版本的 `sqlite3_prepare` 在遇到表结构变更或部分错误时表现脆弱。`_v2`（Version 2）版本在内部做了极其智能的重试机制，更加安全稳定。



SQL 执行：`sqlite3_step`

- **原型**：

	```c
	int sqlite3_step(sqlite3_stmt *pStmt);
	```

- **作用**：让编译好的 `sqlite3_stmt` 字节码在 SQLite 的虚拟机里**向前迈出一步**。

- **返回值（非常关键）**：

	- **`SQLITE_ROW`**：代表这行 SQL 查询**拿到了一行数据**。你可以通过 `sqlite3_column_xxx` 系列函数提取这一行各列的值。提取完后，再次调用 `sqlite3_step` 会读取下一行，直到返回 `SQLITE_DONE`。
	- **`SQLITE_DONE`**：代表 SQL 语句**执行完毕**（例如 `INSERT`、`UPDATE`、`CREATE` 执行完了，或者 `SELECT` 已经把所有数据读完了）。



语句句柄销毁：`sqlite3_finalize`

- **原型**：

	```c
	int sqlite3_finalize(sqlite3_stmt *pStmt);
	```

- **作用**：**垃圾回收！** 销毁编译出来的 `sqlite3_stmt` 字节码对象，释放它占用的堆内存。

- **注意**：每个成功 `prepare` 的语句句柄，都必须对应一个 `finalize`，否则会导致**内存泄漏**。



数据库关闭：`sqlite3_close`

- **原型**：

	```c
	int sqlite3_close(sqlite3 *db);
	```

- **作用**：关闭数据库连接，释放 `sqlite3_open` 分配的系统资源。

- **注意**：在调用 `sqlite3_close` 之前，必须确保所有由该数据库生成的 `sqlite3_stmt` 已经通过 `sqlite3_finalize` 销毁完毕，否则关闭操作会失败并返回 `SQLITE_BUSY`。



一键式函数 `sqlite3_exec`

- **原型**：

	```c
	int sqlite3_exec(
	  sqlite3 *db,                             /* 数据库句柄 */
	  const char *sql,                         /* 要执行的一条或多条 SQL */
	  int (*callback)(void*,int,char**,char**),/* 回调函数（仅在 SELECT 时有用） */
	  void *arg,                               /* 传递给回调函数的第一个参数 */
	  char **errmsg                            /* OUT: 错误信息 */
	);
	```

- **执行 `CREATE`、`INSERT`、`DELETE` 等无返回值的操作**：

	- 不需要关心数据。回调函数（第三个参数）传 `NULL` 即可

	- ```c
		sqlite3_exec(db, "CREATE TABLE t(x); INSERT INTO t VALUES(1);", NULL, NULL, NULL);
		```

- **执行 `SELECT` 查询数据**：

	- SQLite 每查到一行数据，就会**自动调用一次**你写的回调函数。



[具体的API使用官方文档](https://sqlite.org/docs.html)

#include <stdio.h>

int queryAllCallback(void *not_used, int col_count, char **col_values, char **col_names){

    return 0;

int flag = 0;
int queryTableCallback(void *not_used, int col_count, char **col_values, char **col_names){
    /* 以表格的形式展现 */
    if(flag == 0){
        // 打印表头分割线
        fprintf(stdout, "---------------------------------------------------------------------------------------------------------------------------------\n");
        for(int i = 0; i < col_count; ++i){
            // 使用 %-12s 强制左对齐并占位 12 个字符宽度（最后一列简历较长，给宽一点）
            if (i == col_count - 1) {
                fprintf(stdout, "%-30s\n", col_names[i]);
            } else {
                fprintf(stdout, "%-12s\t", col_names[i]);
            }
        }
        // 打印表头分割线
        fprintf(stdout, "---------------------------------------------------------------------------------------------------------------------------------\n");
        flag = 1; // 整个表头打印完后再标记为 1
    }

    // 2. 打印当前行的数据
    for (int i = 0; i < col_count; ++i) {

        if (i == col_count - 1) {
            fprintf(stdout, "%-30s\n", val);
        } else {
            fprintf(stdout, "%-12s\t", val);
        }
    }
    return 0;
}

void queryValue(sqlite3 *db){
    /* SQL防注入 防止条件中出现，OR 1=1 这种条件，这个条件会将数据所有数据打印出来 */
    sqlite3_stmt *stmt;         // 被数据库编译优化后的、随时可以执行的 SQL 运行实体。
    // 1. 使用 "?" 作为参数占位符，不进行任何字符串拼接
    const char *sql = "SELECT * FROM stu_test WHERE sex = ? AND salary > ?;";

    // 2. 预编译 SQL 语句
    if (sqlite3_prepare_v2(db, sql, -1, &stmt, NULL) == SQLITE_OK) {
        
        // 3. 将用户输入的安全地“绑定”到占位符上
        // 此时即使输入包含 ' OR '1'='1，数据库也只会把它当成一个普通的“字符串字面量”，绝不会当成指令执行
        sqlite3_bind_text(stmt, 1, "1", -1, SQLITE_STATIC);
        sqlite3_bind_text(stmt, 2, "11000", -1, SQLITE_STATIC);
        
        // 4. 获取结果集的总列数（例如 id, name, sex... 一共有 8 列）
        int col_count = sqlite3_column_count(stmt);

        // 5. 打印表头（只打印一次）
        printf("+------+----------+------+--------------+--------------+--------------+----------+------------------------------------------+\n");
        printf("|");
        for (int i = 0; i < col_count; i++) {
            // sqlite3_column_name 可以获取当前列的列名
            const char *col_name = sqlite3_column_name(stmt, i);
            printf(" %-10s |", col_name ? col_name : "NULL");
        }
        printf("\n+------+----------+------+--------------+--------------+--------------+----------+------------------------------------------+\n");

        // 6. 使用 while 循环，一行一行地读取并打印数据
        int row_count = 0;
        while (sqlite3_step(stmt) == SQLITE_ROW) {
            row_count++;
            printf("|");
            for (int i = 0; i < col_count; i++) {
                // 使用 sqlite3_column_text 获取当前行、当前列的文本数据
                // 注意：哪怕数据库存的是数字，这个函数也会自动帮你转换成字符串，非常方便
                const unsigned char *col_val = sqlite3_column_text(stmt, i);
                
                printf(" %-10s |", col_val ? (const char *)col_val : "NULL");
            }
            printf("\n");
        }

        // 7. 打印表格底边框
        printf("+------+----------+------+--------------+--------------+--------------+----------+------------------------------------------+\n");

        if (row_count == 0) {
            printf("没有查询到符合条件的数据。\n");
        } else {
            printf("共查询到 %d 条数据。\n", row_count);
        }
    }
    sqlite3_finalize(stmt); // 释放资源
}
