## 入门知识

- 并发与并行
	- 并发：两个 或者 多个 事情**同一时间段**内发生
	- 并行：两个 或者 多个 事情 **同一时刻** 发生

>注：在单核CPU无法做到真正意义上的并行运行，即微观下同一时刻处理线程，实际是cpu在快速调度（线程之间的切换），宏观上表现为并行处理。

- 线程 和 进程

	- 线程：类似工人。 线程是进程中的一个执行单元，负责当前进程中程序的执行。
		- 一个进程中至少有一个线程。
		- 一个进程中是可以有多个线程的，这个应用程序也可以称之为多线程程序  
		- 是操作系统**调度执行**的基本单位
	- 进程：类型工厂，内部有工人 （线程）+ 设备（任务）。
		- 每个进程都有一个独立的内存空间和系统资源  
		- 一个应用程序可以同时运行多个进程  
		- 进程也是程序的一次执行过程，是系统运行程序的基本单位；
		- 系统运行一个程序即是一个进程从创建、运行到消亡的过程。
		- 是操作系统**资源分配**的基本单位  

- cpu调度算法

	- 

	- | 算法                        | 基本规则                               | 是否抢占           | 优点                         | 缺点                                           | 典型场景                           |
		| :-------------------------- | :------------------------------------- | :----------------- | :--------------------------- | :--------------------------------------------- | :--------------------------------- |
		| **先来先服务 (FCFS)**       | 按到达顺序执行                         | 否                 | 简单、公平                   | 平均等待时间长，护航效应（短作业被长作业阻塞） | 批处理系统                         |
		| **最短作业优先 (SJF)**      | 选择预计运行时间最短的作业             | 非抢占             | 平均等待时间最小（理论最优） | 无法预知作业长度，可能导致长作业饥饿           | 作业调度（不能进行进程调度）       |
		| **最短剩余时间优先 (SRTF)** | 每次选择剩余时间最短的进程             | 是                 | 平均等待时间更优，响应更快   | 同上，且频繁抢占开销大                         | 分时系统                           |
		| **优先级调度**              | 选择优先级最高的进程                   | 可抢占/非抢占      | 可区分重要性                 | 低优先级可能饥饿（需老化）                     | 实时/优先级敏感系统                |
		| **时间片轮转 (RR)**         | 每个进程执行固定时间片，循环           | 是                 | 响应快，公平                 | 时间片选择敏感（过大变FCFS，过小切换开销大）   | 分时/交互系统                      |
		| **多级队列**                | 多个独立队列，各用不同算法             | 是（队列间可抢占） | 灵活，可区分不同类型任务     | 队列间调度策略难调优，可能饥饿                 | 混合负载系统                       |
		| **多级反馈队列 (MLFQ)**     | 进程可在队列间迁移，优先执行短作业     | 是                 | 兼顾响应和吞吐，避免饥饿     | 实现复杂，参数需调优                           | 现代通用OS（如Windows、Linux早期） |
		| **完全公平调度 (CFS)**      | 选择虚拟运行时间（vruntime）最小的进程 | 是                 | 公平，吞吐高，延迟低         | 对交互任务需额外优化（如自动分组）             | Linux 内核（当前）                 |

	- java使用的是抢占式调度算法

## java线程基础知识

### 线程的简单使用

- **创建线程（官方的）**

	1. 继承Thread
		- 重写父类的run() 【run()方法里面放具体的执行逻辑】
	2. 实现Runnable接口
		- 实现Runnable的run()方法

- 启动线程

	1. 使用Thread创建的线程，直接通过`对象.start();`启动
	2. 使用Runnable创建的线程，先`Thread  new Thread(Runnable 对象);` 后`Thead对象.start();`启动

- Runnable和Thread的选择

	- 一般选择Runnable
		- 可以继承其他类
		- 这个Runnable可以共享（多个线程使用一个资源）
		- 将线程 和 任务 分离

- start() 和 run()的区别

	- start()：并不是真正的启动线程，只会通知操作系统有线程需要启动（java调用start()）
	- run()：启动的线程需要完成的逻辑任务。本质是在java层面给操作系统预留的回调方法

- main方法本身也默认分配了一个线程（主线程）

- 线程控制相关API

	- | 方法                        | 作用                                                         | 关键点                                                       |
		| --------------------------- | ------------------------------------------------------------ | ------------------------------------------------------------ |
		| `Thread.sleep(long ms)`     | 让当前线程**休眠**指定毫秒                                   | **不释放锁，抱着锁睡觉**                                     |
		| `setName(String name)`      | **修改线程名字**                                             | 方便日志调试                                                 |
		| **`join()`**                | **等待该线程执行完毕**                                       | 谁调用，就等谁执行完                                         |
		| `setPriority(int priority)` | 设置线程优先级                                               | 1~10，仅供 CPU 参考，不是绝对                                |
		| `Thread.yield()`            | **线程礼让**                                                 | 让出 CPU，重新竞争，让谁执行由 CPU 决定                      |
		| `setDaemon(true)`           | **设置为守护线程**（针对JVM而言，换句话说，守护的对象是jvm中所有的非守护进程） | **必须在 start () 之前设置**。守护的用户线程全部结束，守护线程自动结束 |

- **线程停止API**

	- 两种方法：强制停止 和 中断停止

	- | 分类         | 方法                   | 作用                   | 特点                                                         |
		| ------------ | ---------------------- | ---------------------- | ------------------------------------------------------------ |
		| 强制停止     | `stop()`               | 强制终止线程           | 已废弃，不安全，易造成数据丢失、资源未释放，后续版本使用会抛出UnsupportedOperationException |
		| **中断相关** | `interrupt()`          | 发送中断信号           | 不立即停止线程，仅将**中断标志设为 true**                    |
		| **中断相关** | `isInterrupted()`      | 判断线程是否被中断     | **不清除**中断标志                                           |
		| **中断相关** | `Thread.interrupted()` | 判断当前线程是否被中断 | **会清除**中断标志（自动重置为 false）                       |

	- 中断补充

		- 中断 -》 是一种协商机制，具体停止需要线程自己做出相关动作

		- 在使用`sleep() / wait()` 时被中断，线程会先抛出异常，然后清理中断标志位，让线程不能正常退出

			- 解决方法：在异常抛出前（在catch中），自己发生中断信号`Thread.currentThread().interrupt()`

			- ```java
				class InterruptThread1 extends Thread{
				    @Override
				    public void run() {
				        while (true){
				            System.out.println(Thread.currentThread().getName());
				            try {
				                Thread.sleep(1000);
				            } catch (InterruptedException e) {
				                /* 当使用sleep时，被中断，线程会抛出异常，并且会清空标志位 */
				                Thread.currentThread().interrupt();
				                e.printStackTrace();
				            }
				            if(Thread.currentThread().isInterrupted()){ /* 判断中断标志位 不会清空标志位 */
				                System.out.println(Thread.currentThread().isInterrupted());
				                break;
				            }
				
				        }
				    }
				}
				```

### 多线程的生命周期

- ```mermaid
	stateDiagram-v2
	    direction LR
	    [*] --> 新建(NEW) : new Thread()
	    新建(NEW): 新建<br>创建线程对象
	    新建(NEW) --> 就绪(RUNNABLE) : start()
	    
	    就绪(RUNNABLE): 就绪<br>有执行的资格，没有执行权
	    就绪(RUNNABLE) --> 运行(RUNNING) : 获得CPU时间片
	    运行(RUNNING) --> 就绪(RUNNABLE) : yield() / 时间片用完 / 被别人抢到CPU执行权
	    
	    运行(RUNNING) --> 阻塞(BLOCKED) : 等待同步锁(synchronized)
	    阻塞(BLOCKED): 阻塞<br>没有执行资格，没有执行权
	    阻塞(BLOCKED) --> 就绪(RUNNABLE) : 获得锁
	    
	    运行(RUNNING) --> 无限等待(WAITING) : wait() / join()
	    无限等待(WAITING): 无限等待<br>没有执行资格，没有执行权
	    无限等待(WAITING) --> 就绪(RUNNABLE) : notify() / 中断
	    
	    运行(RUNNING) --> 计时等待(TIMED_WAITING) : sleep(ms)/wait(ms)/join(ms)
	    计时等待(TIMED_WAITING): 计时等待<br>没有执行资格，没有执行权
	    计时等待(TIMED_WAITING) --> 就绪(RUNNABLE) : 时间到 / 中断
	    
	    运行(RUNNING) --> 终止(TERMINATED) : run()执行完毕 / 异常 / stop()(过时)
	    终止(TERMINATED): 死亡<br>对象变成垃圾，等待回收
	    终止(TERMINATED) --> [*]
	```
	
- 线程的状态（`Thread.State`  枚举类; `getState` 获取状态 ）

	1. **新建（NEW）**
	2. **就绪（RUNNABLE）**
	3. **阻塞（BLOCKED）**
	4. **等待（WAITING）**：需要别人叫醒
	5. **计时等待（TIMED_WAITING）**：可以自己苏醒
	6. **终止（TERMINATED）**

### 线程安全

- 前提条件：
	- 共享资源
	- 很多线程同一时刻访问这个资源
- 每个类都有唯一一把锁（类锁）
- 每个对象也有唯一一把锁（对象锁）
- 使用同步方法解决

#### 解决方法一：synchronized （jdk官方提供）

- 执行synchronized 相关的方法 或者 块时，其他线程会先获取 对象（或者 类）上的锁，如果锁被占用，那么其他线程会等待该线程解锁
- 给方法上锁：
	- 修饰普通方法，获取的是  对象上的锁，多在Runnable中使用
	- 修饰static方法，获取的是 类上的锁，多在Thread中使用
- 给块上锁
	- `synchronized(对象){} `：获取 对象上的锁，多在Runnable中使用
	- `synchronized(类名.class){}`：获取 类上的锁，多在Thread中使用

#### 解决方法二：Lock锁

- 是用户层面上，java代码实现的锁，需要手动加锁、解锁
- 出现原因：早期，synchronized底层利用操作系统的互斥，导致每次都需要用户态切换核心态，性能消耗大、效率低。不过，后续因为Lock锁，synchronized进行了升级。
- 使用
  - Lock是一个接口，有一个ReentrantLock实现
  - lock() 上锁
  - unlock() 解锁

- 使用规范

  - ```java
  	Lock l = ...; l. lock(); try {   // access the resource protected by this lock } finally {   l. unlock(); }
  	```

- sychronized 和 lock 区别

	- | sychronized                                                  | lock                                                         |
		| ------------------------------------------------------------ | ------------------------------------------------------------ |
		| 可重入锁（自己获取相同的锁，可以打开用这个锁锁住的其他方法） | 可重入                                                       |
		| 不可中断（当线程尝试获取 `synchronized` 锁时，如果锁已被其他线程持有，该线程会**一直阻塞**（BLOCKED 状态），**无法响应中断**。即使调用 `Thread.interrupt()`，该线程也不会被唤醒，只会等待锁释放后才检查中断标志（通常不会处理）） | 可中断（通过 `lockInterruptibly()` 方法，线程在等待锁的过程中可以响应中断，抛出 `InterruptedException`，从而提前退出阻塞。） |
		| 不可超时                                                     | 可超时                                                       |
		| 属于JVM层面                                                  | 属性java层面                                                 |

		



### wait 与notify

- 前提条件
	- 只能在synchronized中使用
	- 只能在对象上使用
	- 针对的是对象上的线程
	- 每个对象都会有一个 wait set池（等待池）
- `对象.wait()` 该对象上的线程在等待
	- 当调用 wait() 时，该线程就会wait，将该线程放入该对象中的wait set池
	- **wait()后，会释放锁**
- `对象.notify() `唤醒
	- 当调用notify()时，会去该对象的wait set池中唤醒线程（随机唤醒）
- `对象.notifyAll()` 唤醒该对象的wait set池的全部线程

### 死锁

- 两个或者多个线程互相占有对方需要的资源的一部分，互相都进入加锁状态，因为资源不完整，导致互相都结束不了线程
- 解决方法：
	- 加锁和释放锁保证一致性
